## 2026-11-20：Dotcpp 2240 删除数组零元素（在线提交通过）

- **轨道**：C 语言 / Dotcpp
- **题目与来源**：2240《删除数组零元素》，`https://www.dotcpp.com/oj/problem2240.html`
- **训练目标**：原地数组压缩、读写双下标、函数职责划分、数组参数、返回有效长度。
- **用户初始思路**：能写出读入循环和 `count` 的想法；在提示下完成 `if (a[i] != 0) { a[count] = a[i]; count++; }`。
- **错误与修正**：
  - `scanf` 漏写 `&`，以及把 `a[n]` 写在读取循环中而非 `a[i]`。
  - 输出时没加数字间分隔符，导致数字粘连。
  - 将输入输出写入 `CompactIntegers`，`main` 反而没有准备 `n` 和 `a`；不完整的函数参数和返回值。
  - 在 `n` 未初始化时声明 `int a[n]`。
- **最终思路**：`main` 读入与输出；`CompactIntegers` 通过数组参数原地保留非零元素，`return count` 返回新长度。输入、处理、输出分工明确。
- **复杂度**：单次线性遍历，时间 `O(n)`，额外处理空间 `O(1)`（不计 `main` 中的输入数组）。
- **验证证据**：用户明确反馈 Dotcpp **在线提交通过**；仓库代码据本次对话整理，未另行宣称编译或测试。
- **掌握度**：**C（引导完成）**；成功通过，但函数封装曾多次依赖提示和完整参考代码。
- **工程迁移**：适用于原地过滤采样值、整理固定长度缓存；区分数组容量与有效长度。
- **下一步**：隔次在不看答案时重写删除指定值的数组压缩函数，再评估是否提升至 B/A。

## 2026-11-16：建立长期学习系统

### 本次决策

将个人编程学习分成三条主线：

1. C 语言基础与工程编码：使用 Dotcpp，由教师筛选题目，当前优先恢复独立编码能力。
2. C++ 算法与数据结构：使用 LeetCode，训练算法建模、数据结构选择和复杂度分析。
3. 数学思维：偶尔穿插短题，训练逻辑、不变量、必要条件与充分条件，不设硬性题量。

### 教学方式

- 先由用户独立思考和尝试，教师按提示等级逐步引导。
- 代码由用户实际编写；必要时提供局部示例或完整参考实现，但必须安排解释和复写。
- 每题检查边界、复杂度、数据结构选择和验证状态。
- 结合真实嵌入式工程讨论迁移价值，但不为了“用算法”而强行引入复杂结构。
- 根据重复错误和独立复写结果动态调整课程。

### 当前发现

- 用户能完成部分数组和滑动窗口代码，但对下标边界、窗口有效长度、队列候选维护等机制需要通过手动模拟建立直觉。
- 用户关注 AI 时代是否还需要手写。当前共识：不与 AI 比代码产量；仍要保留独立分析、编写核心逻辑、判断方案和验证结果的能力。
- 真实 MCU 工作不一定需要复杂算法。固定数量的小规模端口管理通常数组遍历更合适；数据结构选择要看数据规模、操作类型、频率、资源和并发约束。
- AI 可以承担代码生成和 Review，但需求定义、资源取舍、验证和最终验收不能省略。
